# دليل واجهة الصالة LogicFit_Angular

المشروع `LogicFit_Angular` هو الواجهة التشغيلية لكل صالة، وليس لوحة مالك منصة الـSaaS.
المسارات الرئيسية محمية بـ`authGuard` ثم guard للدور. عدم ظهور شاشة أو زر لا يساوي
منح صلاحية؛ API هو الذي يفرض الهوية والـTenant والسياسات.

## الدخول والتوجيه

| المستخدم | نقطة الدخول بعد المصادقة | الاستخدام |
|---|---|---|
| Owner / Manager / Receptionist / Accountant | `/owner/...` | back-office للصالة وفق Permissions. |
| Coach / Trainer | `/coach/...` | المتدربون المعينون والبرامج والمواعيد. |
| Client | `/client/...` | بوابة العضو وبياناته الشخصية فقط. |
| صالة محجوبة | `/gym-unavailable` | حالة صالة معلقة/منتهية/مؤرشفة؛ متاحة للعرض حتى إن انتهت الجلسة. |

تسجيل المستخدم العادي عبر `/auth` ينشئ Client فقط؛ لا يسمح للمتصفح باختيار Role.
حسابات الموظفين تنشأ من مسار التشغيل المصرح به.

## دليل مالك الصالة وموظفي Back-office

| المجال | الشاشة/المسار | من يستخدمها | ما الذي يديره؟ |
|---|---|---|---|
| المتابعة | `/owner/dashboard`, `/owner/operations` | Owner وما تسمح به الصلاحيات | مؤشرات التشغيل والتنبيهات اليومية. |
| الأعضاء | `/owner/clients`, `/owner/membership-cards`, `/owner/gate-access` | `ManageMembers`, `ViewMembers`, `ManageAttendance` | أعضاء الصالة، بطاقات العضوية، دخول البوابة. |
| الاشتراك والحضور | `/owner/subscription-plans`, `/owner/subscriptions`, `/owner/attendance` | `ManageClientSubscriptions`, `ManageAttendance` | خطط عضو الصالة، دورات العضوية والحضور. |
| الفروع | `/owner/branches`, `/owner/rooms`, `/owner/equipment`, `/owner/maintenance` | `ManageBranches` | الفروع، القاعات، الأجهزة والصيانة. |
| الحصص | `/owner/group-classes`, `/owner/class-schedules` | الصلاحية المعينة | تعريف الحصص وجدولتها والحجوزات والحضور. |
| المال | `/owner/invoices`, `/owner/payments`, `/owner/expenses`, `/owner/expense-categories`, `/owner/coupons`, `/owner/tax-settings` | `ManageFinance` أو `ManageSettings` | الفواتير والمدفوعات والمصروفات والضرائب والكوبونات. |
| البيع والمخزون | `/owner/pos-sales`, `/owner/products`, `/owner/product-categories`, `/owner/stock`, `/owner/suppliers` | `ManagePOS`, `ManageInventory` | نقطة البيع، المخزون والشراء والموردون. |
| فريق العمل | `/owner/employees`, `/owner/shifts`, `/owner/leaves`, `/owner/commissions`, `/owner/payroll` | `ManageEmployees`, `ManageFinance` | الموظفون والورديات والإجازات والعمولات والرواتب. |
| الإعدادات | ملف الصالة والمستخدمين والأدوار حسب القائمة والصلاحيات | Owner/Manager | بيانات الصالة وشعارها وإدارة التفويض. |

### مسؤولية كل موظف

- **Owner:** يضبط الصالة والفروع والموظفين والضوابط المالية، مع عدم تجاوز حدود خطة
  الـSaaS. لا يملك إدارة صالات أخرى أو خطط المنصة المركزية.
- **Manager:** ينجز تشغيل الصالة في حدود Permissions الممنوحة له؛ لا تفترض أنه Owner.
- **Receptionist:** يركز على العضوية، الحضور، الحجز والاستقبال؛ امنع الوصول للمال أو
  الإعدادات ما لم تمنحه صراحة.
- **Accountant:** يدير الجانب المالي داخل الصالة. التعديل/الإلغاء المالي يتبع قواعد
  فواتير الصالة والسجل، ولا يمنحه صلاحيات منصة الـSaaS.

## دليل المدرب

| المسار | الاستخدام |
|---|---|
| `/coach/dashboard` | ملخص عمل المدرب. |
| `/coach/trainees` | المتدربون المعينون للمدرب فقط. |
| `/coach/workout-programs` | برامج التمرين والروتينات. |
| `/coach/diet-plans` | خطط التغذية والوجبات. |
| `/coach/appointments` | المواعيد مع المتدربين. |
| `/coach/chat` | المحادثات المصرح بها. |
| `/coach/challenges` | التحديات الرياضية. |
| `/coach/exercises`, `/coach/foods` | مكتبة التمارين والأطعمة. |

لا يحق للمدرب تعديل مدرب آخر أو عضو غير معين له أو الوصول إلى مال الصالة لمجرد معرفة
معرّف السجل. يجب أن يثبت Backend علاقة CoachClient والـTenant في كل طلب.

## دليل العضو Client

| المسار | الاستخدام |
|---|---|
| `/client/dashboard` | ملخص العضوية والنشاط. |
| `/client/my-programs` | برامج التمرين الموجهة له. |
| `/client/my-diet-plans` | خططه الغذائية. |
| `/client/my-subscriptions` | عضوياته ومدتها وحالتها. |
| `/client/my-measurements` | قياساته الشخصية. |
| `/client/my-coach` | المدرب المرتبط به. |
| `/client/appointments` | المواعيد الخاصة به، مع الحالة والوقت والمدرب ورسالة واضحة عند الفراغ أو فشل التحميل. |

هذه المسارات لا تقبل `clientId` من الواجهة لتحديد شخص آخر؛ الهوية في Token هي مصدر
العميل. أي صورة أو بيانات صحية تعامل كبيانات حساسة ولا توضع في مسار public static.

## Flows تشغيلية للصالة

### عضو جديد وحضور

1. موظف مصرح ينشئ/يجد العميل ويحدد بياناته.
2. ينشئ أو يربط اشتراك العميل وفق خطة الصالة.
3. يصدر بطاقة عضوية إن كانت السياسة تستخدمها.
4. تسجيل الدخول للبوابة ينشئ Attendance بعد التحقق من الحالة والملكية.
5. الخروج يحدث `check-out` للسجل المفتوح الصحيح، لا سجل عشوائي بالمعرّف.

### مدرب وبرنامج

1. Owner/Manager يربط Coach بالعميل.
2. المدرب ينشئ برنامج تمرين/خطة غذاء للعميل المخصص فقط.
3. العميل يقرأ البرنامج من بوابته؛ لا يعدل تعريف المدرب أو أعضاء آخرين.
4. التغييرات المهمة تترك Audit/تاريخاً حيث يدعم المجال ذلك.

### بيع ومخزون

1. عملية POS تنشئ Sale وسطورها.
2. حركة مخزون تسجل سبباً ومرجعاً ولا تعدل الرصيد فقط بدون حركة.
3. الشراء والموردون والمنتجات ضمن Tenant واحد.
4. التقارير المالية تقرأ الأثر المسجل؛ لا تعتمد على إجمالي واجهة فقط.
